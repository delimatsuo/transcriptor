no source authority until the owner names this package's exact commit/tree and
accepts the API, path, and claim-ceiling conditions below.

## Decision corridor

Proceed with G3B as a source-only, generated-fixture macOS companion model.
The selected native boundary is AVAudioEngine/Core Audio for microphone input
and ScreenCaptureKit audio output on macOS 13.0 or later. Native adapters may be
declared for the later implementation, but this package authorizes no
permission prompt, device access, capture stream, provider, network, cloud,
credential, deployment, release, or real-data action.

## Required source behavior

The later source implementation must demonstrate with generated bytes only:

1. independent microphone/system-audio source identity, sequence, sample-rate,
   timestamp, route-health, permission, interruption, and degraded-state axes;
2. canonical v2 framing, typed retry identity, sample-rate-derived custody,
   per-source/session quotas, overflow, exact gaps, and unknown-end recovery;
3. local privacy discard and timeout zeroization without claiming provider
   forwarding or durable gateway coverage;
4. pause, stop, finalization, upgrade, deletion, worker/effect quiescence,
   stale-response fencing, and late-callback rejection;
5. injected native adapters whose offline tests never request permissions,
   open a device, start a stream, or use a virtual/default-route path; and
6. content-free diagnostics, guards, artifact scans, and no raw-audio files.

## Required verification before publication

The future implementation owner must record a clean exact commit/tree, exact
path-set equality, repeated network-denied Swift tests, API-availability and
state-fault tests, race/crash/recovery tests, artifact/credential/endpoint
scans, and an owner architecture/security/privacy/claim-ceiling attestation.
Evidence may claim only deterministic source/offline behavior. A later named
controlled-fixture or physical-device run requires a separate authorization.

## Stop conditions

Stop without source edits if work requires an excluded path, dependency,
permission prompt, live device, native stream, network/package fetch,
provider/cloud API, credential, durable raw-audio storage, virtual/default
route, real audio, candidate data, or a protocol-semantic change.
