# Week 4: authenticated internal tenancy

## Scope

Add the smallest safe authentication boundary for the internal second-user
interview: Google sign-in in the web client, Firebase Admin ID-token
verification in the backend, server-derived `uid` and configured internal
`org_id` on every session and durable interview record, and owner/org filtering
for every session subresource. The Admin SDK continues to use ADC and therefore
bypasses Firestore rules; this is attribution and internal tenancy, not a hosted
security boundary. Commercial/hosted isolation remains a later gate.

## Security and lifecycle contract

- Admission requires a verified Firebase token (`check_revoked=True`, verified
  email, expected audience/project, and an exact configured internal email
  allowlist). The request cannot supply or override `owner_id` or `org_id`.
- HTTP requests fail closed with `401` and a Bearer challenge when credentials
  are missing, malformed, expired, revoked, wrong-audience, unverified, or not
  allowlisted. Authenticated access to another owner's object is a non-
  enumerating `404`.
- An authenticated HTTP call mints a cryptographically random, short-lived,
  single-use WebSocket ticket bound to `uid + org + session + purpose + expiry`.
  The browser offers only that ticket in `Sec-WebSocket-Protocol`; the ticket
  is consumed atomically before accept and is never logged, echoed, or placed
  in a URL. Reconnects obtain a fresh ticket. A separate idempotent stop-only
  capability keeps an active capture stoppable during logout/token loss.
- The Chrome extension bridge is disabled by default for Week 4. If a later
  owner explicitly enables it, it must use Firebase `Authorization` plus a
  separate owner-bound, expiring, constant-time session capability; it must
  never collide with the app bearer. Every extension route remains parent-
  authorized.
- Legacy records and blobs missing ownership fields are not visible to
  authenticated users and are not auto-claimed. A versioned dry-run inventory
  is available at `backend/scripts/inventory_legacy_scope.py`; it must be run
  and reviewed before any quarantine or owner-approved backfill migration.
  Destructive operations authorize the parent before touching subcollections or
  GCS paths; new blob keys are opaque server-derived identifiers rather than
  candidate filenames. Once owned data exists, rollback means another
  auth-enforcing build or shutdown, never unauthenticated Week 3.
- Auth state is explicit: initializing, signed out, signed in, refresh/error,
  and capture-auth-loss. Token loss or sign-out cannot hide an active capture;
  the stop action remains visible until a confirmed terminal response. A
  confirmed stop precedes sign-out. On `uid` change, requests/reconnects stop
  and transcript, report, notes, briefing, recent-list, and review URL state
  clear synchronously before the new account renders.
- The launch UI is interview-only, uses pt-BR disclosure/preflight copy, shows
  signed-in identity and sign-out, and exposes keyboard/screen-reader status and
  actionable errors. The Playwright bypass is compile/startup gated, fixed to
  synthetic principals, defaults off, and is rejected in production.

## Acceptance matrix

1. Signed-out startup makes zero API/WebSocket calls and shows no interview
   data; sign-in then performs authenticated preflight and starts an interview.
2. Token refresh/revocation during capture leaves recording and stop visible;
   no silent note loss or false completion; sign-out waits for confirmed stop.
3. Account A sign-out → Account B sign-in clears all A state and an A session
   URL returns a non-enumerating not-found response.
4. Unit/API tests cover missing, malformed, expired, revoked, wrong-audience,
   unverified, and unallowlisted tokens; every GET/PUT/POST/DELETE/download,
   report approval/export, extension, and WebSocket path; cross-owner/org
   rejection; no request-supplied ownership override; token-free logs; and
   production bypass refusal, the one-time WS ticket and stop capability, and
   extension capability expiry/rotation. A route-coverage guard proves only
   `OPTIONS` bypasses authentication.
5. No live Firebase, Firestore, provider, deployment, physical-device, or real
   interview evidence is implied by source or synthetic tests.

`firestore.indexes.json` records the owner/org/start-time query required by the
authenticated recent-session list. Deploying this index is a separate hosted
gate; this PR does not deploy it.
