# T.A.R.S. Launch Panel — Moderator Synthesis

*Produced 2026-08-03 by an adversarial moderator that read all six independent panel reports, re-verified load-bearing claims against the repository, resolved conflicts, and hunted for shared blind spots. File:line citations were verified at `staging` @ `0e07a29`.*

## 1. Verification of load-bearing claims

**(a) Windows capture — both panelists are right, about different layers.** `backend/audio/capture.py` is pure sounddevice with name-substring device discovery (`find_input_device`, capture.py:17–42) and channel-0 mono extraction (capture.py:95). Any device PortAudio can see as an *input* works with zero code — VB-CABLE presents exactly that, so the **skeptic's mechanism claim is verified**. The **Windows engineer is also verified**: upstream PortAudio/sounddevice has no WASAPI loopback, so the virtual-device-free path needs PyAudioWPatch (new capture source code). Lower-risk launch path: **VB-CABLE first** — it is config-only, keeps one identical codebase on both OSes, and the misroute failure class it introduces is *already instrumented*: startup silence detection (capture.py:139–163) and the single-audio-source warning (main.py:320–340). Its real risk is routing UX ("Listen to this device" so the recruiter still hears the candidate). That's a hours-long spike, not a weeks-long build; PyAudioWPatch is the fallback if routing proves fragile. The skeptic's deeper point survives verification: capture was never the cost — packaging is (see §3.4 for a new fact that shrinks it).

**(b) STT rotation defect — verified exactly as described.** Docstring promises A/B overlap (stream_manager.py:19–28); `_rotate_stream` hard-stops the stream (121–125); `send_audio` silently no-ops while inactive (97–100); `stt_stream_overlap_seconds` exists unused (config.py:66–68); the dedup needed for a real overlap fix already exists (`_last_emitted_end_time`, 171–177). Rotation fires every 270s (config.py:62–64). Launch-blocking, consensus correct.

**(c) Report "mostly a UI gap" — verified, with a critical catch all six missed.** `INTERVIEW_REPORT_PROMPT` (backend/llm/interview_prompts.py:74–139) is a full pt-BR assessment report; `_generate_final_summary` (main.py:388–454) runs it on stop (main.py:512) with CV/JD/briefing context, persists to Firestore (441–446), and the frontend already downloads it (as `.txt`, SummaryPanel.tsx:38). Architect and skeptic confirmed. **But**: the prompt instructs the AI to emit 1–5 competency ratings and a **"Recomendado / Não Recomendado" hire recommendation** (interview_prompts.py:102–133) with no approval gate. The "AI never rates; humans approve" invariant that the architect lists as *kept* (Guardrail 8) and privacy calls load-bearing for LGPD Art. 20 **is already violated by shipped backend code**. The product strategist demanded AI ratings be disabled without knowing they're live. Surfacing this report "as a UI gap" would launch the exact thing three panelists forbid.

**(d) Other spot-checks.** `session_state` never sent: verified — handler returns with only a comment (ws/handler.py:76–85); the WS endpoint (main.py:915–943) only does ping/pong; zero callers repo-wide. FLAC always written: verified (buffer.py:51–53 unconditional open; 76–81 sync write per chunk). `gateway/phase1b/` contains `operator/` but **zero files** — architect's "empty" claim holds in substance. Worktree locations: no conflation — `note-sync-lab` lives in `../Transcriptor-worktrees/`, the four other labs in `build/worktrees/`, and the note-sync `contract.ts` copies are byte-identical (diff verified). Retention 90d: config.py:82, unenforced. Firebase auth scaffold: frontend/src/lib/firebase.ts:4,17. CV/JD ingestion **exists and works**: PDF/DOCX/TXT upload with parsing (main.py:525–559), paste endpoint (562–573), pre-interview CV-vs-JD briefing (576–652).

## 2. Conflict resolution

**Windows-at-launch** (engineer: 1–2 wks feasible / skeptic: cut / strategist: biggest risk). The owner said Windows is required — **no panel can cut it; only Deli can**. Recommendation: a **week-1 decision gate**. Prerequisites: name the actual Windows recruiter and physical machine (engineer's and skeptic's shared precondition); spike VB-CABLE on it (hours, zero code); PyAudioWPatch only if routing fails. Present the fork with real costs at Friday of week 1: **(A)** Windows-at-launch ≈ 1.5–2 of ~7 agent-weeks, mostly packaging, at the cost of report/notes polish; **(B)** macOS launch week 4 + Windows fast-follow with a committed date ~3 weeks later, shipping the full wedge first. I reject the engineer's framing that capture feasibility settles it (packaging on non-engineer machines is unbudgeted in his 1–2 weeks) and reject the skeptic's outright cut (overrides an explicit owner constraint). New fact reducing the gap between them: the torch dependency can be deleted (§3.4), which removes the heaviest, most failure-prone piece of a Windows install.

**Notes depth** (UX: note-sync contract chips / skeptic: dumb textarea). Split the layers: **UX wins the interaction, skeptic wins the plumbing.** Ship the four-chip row (one-tap, wordless, sub-second — UX's core insight is right and matches how recruiters actually behave mid-call), but back it with a plain REST endpoint writing timestamped notes stamped with the current segment id — *not* the 680-line mutation-ledger reducer, which solves offline multi-device sync nobody has. Reuse the `NoteKind` vocabulary so data migrates cleanly to the full contract later. I reject the bare textarea specifically because segment-anchoring is what makes notes usable as report evidence — and it costs one field.

**Report depth** (UX: provenance layers / skeptic: summary+transcript v1). **Skeptic wins on structure, UX wins on presentation, and both must absorb §1(c):** launch = existing generated report + a review screen with edit-before-approve + print-CSS PDF export (not `.txt` — clients receive documents). The four-layer provenance UI is blocked on an evidence-binding intelligence layer that the architect verified does not exist (fixture-authored bindings); it cannot responsibly ship in 6 weeks. **Mandatory addition no panelist scoped:** either strip the 1–5 ratings/recommendation from `INTERVIEW_REPORT_PROMPT` or hard-gate the whole report as an editable draft behind an explicit "Aprovar" action with AI-draft labeling. This is 1–2 days and is non-negotiable before any colleague sees a report.

**Auth timing** (privacy: launch-blocking / skeptic: week 4). **Recast blockers by event, not by date.** Privacy's real launch-blockers (FLAC-off, disclosure flow, working deletion, legacy-data purge) bind at the **first real-candidate interview — which the skeptic schedules for week 1**. So they are week-1 work either way; privacy is right that they precede "launch," skeptic is right that *login* can wait for the second user. But the skeptic's week-4 auth is thinner than he thinks: every machine runs the Admin SDK with a service account that bypasses Firestore rules — Google sign-in without credential thinking is cosmetic isolation (see §3.5). Week 4: sign-in + owner-stamping + list filtering, plus a documented shared-trust statement for the internal period.

## 3. Blind spots — what all six missed

1. **AI hire recommendation is already in production code** (§1c). The single most consequential finding: everyone's invariant, nobody checked the prompt.
2. **Past sessions can't be reviewed and crashed sessions can never get a report.** `get_session`/`get_transcript` read the in-memory session manager, not Firestore (main.py:663–678); `_generate_final_summary` reads memory too (main.py:392); orphan detection only logs (main.py:102–105). Transcripts *are* persisted per final segment (main.py:256), so the data survives — but after any backend restart it's unreachable through the API. One "regenerate/report-from-Firestore" path is simultaneously the **crash-recovery**, **mid-week-app-update**, and **review-yesterday's-interview** answer. The skeptic's week-3 "report from existing endpoints" silently assumes the process never restarts. This must land before the report screen.
3. **Nobody computed the GCP bill or noticed the cost/privacy tension.** The pipeline streams *all* audio continuously on **two** STT streams ("Send all audio continuously," main.py:174–176) — a 90-min interview bills ~180 STT-minutes; suggestions re-send the full CV+JD+briefing every 5th final segment (main.py:285–286, 347–365) with no caching — and privacy's ZDR posture *requires* caching off, raising token cost further. Likely single-digit dollars per interview, but it's unmeasured and the suggestion cadence is also partly driven by the recruiter's own mic segments (counter increments on any final segment, main.py:275–276). Action: measure on the first dogfood interview; cheap prompt restructuring if ugly.
4. **A heavyweight dependency nobody needs: torch.** `torch==2.5.1`/`torchaudio`/`silero-vad` are pinned (requirements.txt:14–16) for a VAD that is **not wired into the live pipeline** — only `backend/config.py` and the orphaned `backend/audio/vad.py` reference it. Deleting it shrinks the Windows/macOS install by gigabytes and removes the most fragile piece of non-engineer machine setup. Directly changes the Windows cost debate; nobody saw it.
5. **Credential onboarding is the real auth boundary.** Every colleague's machine gets a service account whose Admin SDK reads *all* sessions regardless of app-level auth. Also STT residency: chirp_3 only runs in `us`/`eu` (config.py:53–55) — privacy's São Paulo preference is impossible for STT; transfer mechanism is unavoidable, full stop.
6. **Deletion cascade misses GCS.** Uploaded CVs go to GCS and extracted CV text into Firestore metadata (main.py:548–557); privacy's cascade list named neither.
7. **One-machine reality confirmed** — no panelist made the two-machine error (skeptic framed it correctly), but its corollary went unstated: backend, browser, Meet, and FLAC encode all compete on one laptop during a live call; the sync FLAC write on the event loop (buffer.py:76–81) disappears with FLAC-off, which is now a *performance* fix too.
8. **The 2-person E2E test gates everything.** Every panel conclusion rests on a pipeline never verified end-to-end with a real second speaker. It must be week 1, macOS, before any Windows decision.

## 5. Owner decision list (ordered by plan impact)

1. **Windows gate (end of W1):** who is the actual Windows recruiter, on what machine — and given spike results, launch-with-Windows (option A) or macOS-first + dated fast-follow (option B)? *Recommended default: B unless the spike is clean and a real W1 Windows user exists.*
2. **AI ratings:** strip the 1–5 ratings + recommendation from the report, or keep as clearly-labeled draft behind mandatory approval? *Default: keep, hard-gated — it's the Art. 20 posture and the sales pitch.*
3. **First-real-candidate authorization + consent wording** — invisible capture vs transparent copilot decides positioning and the W1 dogfood. *Default: disclose (privacy's verbal-confirmation flow); "transparent copilot."*
4. **Legacy 16 sessions + 4 PDFs:** delete or regularize? *Default: delete before W1 dogfood.*
5. **Client report format** (PDF/DOCX, Ella template, structure) — the W3 exporter should clone it, not invent. *No default possible; only Deli knows.*
6. **Notes+report vs coverage** as the launch differentiator. *Default: notes+report (five of six agree; coverage's intelligence layer doesn't exist).*
7. **Retention:** is enforced 90d right per Ella's mandate contracts? *Default: yes, with Firestore TTL actually enforced.*
8. **Shared service-account trust** on every internal machine until the commercial phase — acceptable? Who is the encarregado/DPO? *Default: accept internally, document it, name Deli DPO interim.*
9. **Screen-share discipline:** can tab-share-only be mandated internally (unlocks PiP compact mode safely)? *Default: yes, via onboarding checklist.*
10. **Controller structure with clients** (sole vs co-controller) — shapes notices/contracts, not the build. *Defer to counsel; draft LIA assumes sole controller.*
11. **Meet extension officially dead?** *Default: yes — cut; dual-stream labels are the baseline.*

**Bottom line:** the panel converged more than it disagreed; the two real fights (Windows, auth) dissolve into a week-1 evidence gate and event-based sequencing. The most dangerous consensus error was unanimous: everyone assumed the human-judgment invariant was intact while `INTERVIEW_REPORT_PROMPT` ships AI hire recommendations today — fix that before any colleague, or any candidate, meets this product.
